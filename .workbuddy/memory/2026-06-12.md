# 2026-06-12 工作记录

## 配置体系重构（YAML 分层 + Pydantic 类型安全）

### 背景
项目配置参数散落在 `.env`、扁平 `profiles/*.yaml`、`runtime/runtime_config.py` 及代码各处，重复严重、维护困难。

### 已完成的改动

1. **新增 `profiles/base.yaml`**
   - 收集所有平台通用默认值，按层级组织（`llm` / `rag` / `speech` / `protocol` / `rewrite` / `hardware` / `debug` / `repeat` / `build`）

2. **重写 7 个平台 profile**
   - `windows.yaml`、`radxa.yaml`、`radxa_extreme.yaml`、`radxa_full.yaml`、`radxa_light.yaml`、`text_mvp.yaml`、`voice_mvp.yaml`
   - 从"自包含重复默认值"改为"仅写与 base.yaml 的差异"

3. **新增 `app/settings.py`**
   - 统一配置加载器：递归 merge `base.yaml → {platform}.yaml`
   - Pydantic + pydantic-settings 类型校验 + `.env` 机密注入
   - 提供 `get_settings()` 全局单例

4. **改造 `runtime/runtime_config.py`**
   - 保留 `RuntimeConfig` dataclass 和 `load_runtime_config(profile)` 签名不变（向后兼容）
   - 内部改为调用 `app.settings` 新加载器，再将层级配置扁平化
   - 存量环境变量覆盖映射 `_ENV_FIELD_MAP` 保留，不再扩展

5. **修改 `.env.example`**
   - 大幅瘦身，仅保留 `DEEPSEEK_API_KEY` 等机密
   - 非机密配置全部迁移到 YAML

6. **修改 `pyproject.toml`**
   - core dependencies 新增 `pydantic>=2.0`、`pydantic-settings>=2.0`、`pyyaml>=6.0`

### 验证结果
- `load_settings('windows').speech.tts.backend` → `'sapi'` ✅（差异覆盖生效）
- `load_settings('windows').llm.gpu_layers` → `20` ✅（差异覆盖生效）
- `load_runtime_config('radxa_extreme').llm_ctx` → `768` ✅（向后兼容 facade 正常）
- `load_runtime_config()` 默认加载 → `tts_backend='sherpa'` ✅（base 默认值生效）
