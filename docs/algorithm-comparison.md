Current canonical entry points are `docs/RAIR_RAG_routing_reproduction.md`, `docs/RAIR_RAG_downstream_reproduction.md`, `models/README.md`, and `models/llm/README.md`.

> 基于 MoniBox 端侧离线约束（ARM Cortex-A53、1GB RAM、秒级响应、昂贵黑箱评估），筛选 **SCI 潜力 ≥ 4 星且适用性 ≥ 4 星** 的优化算法，聚焦快速发表 SCI 二区/三区。

## 1. 先明确 MoniBox 的优化问题特征

所有引入的优化算法必须适配以下问题结构：

| 特征         | 具体表现                                               | 对算法的要求                              |
| ------------ | ------------------------------------------------------ | ----------------------------------------- |
| **决策变量** | 权重向量 `w ∈ R^d`，d 通常 3~8                         | 适合连续优化，无需离散/组合优化能力       |
| **目标函数** | 检索排序准确率（NDCG）、安全合规率、回复多样性         | 黑箱、非凸、多峰，解析梯度不可得          |
| **评估代价** | 每次评估需运行完整 RAG 链路（embedding + 检索 + 生成） | 函数评估昂贵，算法应收敛快（<200 次评估） |
| **约束**     | 协议命中率 ≥ 阈值、延迟 ≤ 上限                         | 需支持约束处理（罚函数/修复算子）         |
| **离线性**   | 仅在维护窗口期运行优化                                 | 允许分钟级~小时级运行时间                 |

**结论**：MoniBox 的权重优化是一个**低维（d<10）、昂贵黑箱、带约束的连续优化问题**。

**算力有限场景的核心约束**：
- 每次目标函数评估都需运行完整 RAG 链路，代价极高
- 算法总评估次数必须 < 200 次
- 多目标优化意味着评估次数成倍增加，不适合当前场景
- 任何需要额外局部搜索的混合策略都会快速耗尽评估预算

## 2. 推荐算法（适用性 ≥ 4 星且算力友好）

### 2.1 差分进化（DE / Differential Evolution）

| 维度         | 评估                                                                                               |
| ------------ | -------------------------------------------------------------------------------------------------- |
| **适用性**   | ⭐⭐⭐⭐⭐ 极高。DE 在低维连续优化上公认最强之一，收敛速度通常优于 GA                                   |
| **算力友好** | ⭐⭐⭐⭐⭐ 极高。O(NP × d × G)，NP=20~50，d<10，通常 50~100 次评估即可收敛                              |
| **复杂度**   | O(NP × d × G)，NP=种群规模(20~50)，d<10，完全可接受                                                |
| **改进空间** | 大。可设计自适应 F/CR 参数、多策略 DE（如 jDE、SHADE）                                             |
| **SCI 潜力** | ⭐⭐⭐⭐ 高。Applied Soft Computing、Expert Systems with Applications 等二区期刊对 DE 改进工作接受度好 |
| **推荐策略** | **DE 是算力有限场景下的首选**。收敛快、评估少、低维极强                                            |

**问题建模示例**：
```
编码: x = [w_quality, w_enabled, w_recency, w_diversity]
边界: x_i ∈ [0, 0.1]
评估: 运行完整 RAG 链路 → 计算 NDCG@5 + 安全合规率
策略: DE/rand/1/bin + 自适应 F/CR
总评估次数: NP × G ≈ 30 × 20 = 600 次（benchmark 测试）
           实际 RAG 评估可通过代理模型缩减至 < 100 次
```

### 2.2 麻雀搜索算法 + 混沌初始化 + Levy 飞行（SSA-LF）

| 维度         | 评估                                                                       |
| ------------ | -------------------------------------------------------------------------- |
| **适用性**   | ⭐⭐⭐⭐ 较高。经混沌初始化和 Levy 飞行改进后，在低维连续优化上表现稳定        |
| **算力友好** | ⭐⭐⭐⭐ 较高。O(NP × d × G)，与 DE/PSO 同级，但侦察者机制可能增加无效评估     |
| **复杂度**   | O(NP × d × G)，NP=种群规模(30~50)，d<10，可接受                            |
| **改进空间** | 大。混沌映射、Levy 飞行、自适应警戒值均有明确改进点                        |
| **SCI 潜力** | ⭐⭐⭐⭐⭐ 极高。改进点清晰，实验对比充分即可发二区/三区                        |
| **推荐策略** | **快速发表 SCI 三区的最佳主角算法**。代码简单、改进明确、baseline 对比丰富 |

**关键改进与算力权衡**：
- 混沌初始化：不增加评估次数，仅提升初始种群质量
- Levy 飞行：侦察者阶段以概率执行，可控额外开销
- 自适应警戒值：根据迭代进度动态调整，避免过早收敛到局部最优

## 3. 已删除的算法（算力有限或适应性不足）

| 算法/方向                       | 删除原因                                                                                                    |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| **NSGA-II 系列（多目标）**      | 多目标优化需对每个个体评估多个目标函数，评估次数成倍增加。在 RAG 链路每次评估昂贵的场景下，算力预算迅速耗尽 |
| **DE + 精英局部搜索**           | 精英局部搜索需对最优个体进行多次额外评估，对昂贵黑箱极为不利                                                |
| **GWO + Levy 飞行**             | 适用性仅 3 星，GWO 存在早熟收敛问题，在评估次数受限时易浪费预算                                             |
| **PSO + SA**                    | SA 收敛慢、需大量评估，与算力有限场景矛盾                                                                   |
| **MOEA/D、NSGA-III、MO-CMA-ES** | 多目标 + 理论门槛高，不适合当前场景                                                                         |

## 4. 综合排名与发表建议

| 排名 | 算法                             | 目标期刊档次 | 核心优势                                | 注意事项                                           |
| ---- | -------------------------------- | ------------ | --------------------------------------- | -------------------------------------------------- |
| 🥇    | **SSA + 混沌初始化 + Levy 飞行** | 二区/三区    | SCI 潜力 5 星，改进点最清晰，代码最简单 | 原版适用性 3 星，必须通过混沌+Levy 提升到 4 星以上 |
| 🥈    | **DE / 自适应 DE（jDE, SHADE）** | 二区         | 适用性 5 星，收敛最快，评估次数最少     | 改进空间相对 SSA 较小，需设计更有新意的自适应策略  |

### 投稿策略

```
方案 A（首选，快速发表三区）:
主角算法: SSA + 混沌初始化 + 自适应 Levy 飞行
    → 改进点: Logistic 混沌映射、Levy 飞行局部搜索、自适应警戒值 ST
    → 代码量: < 400 行
    → 对比实验: GA, PSO, DE, GWO, WOA, 标准 SSA（6 个 baseline）
    → 测试函数: 10 个标准 benchmark
    → 应用实验: MoniBox 权重优化（单目标：NDCG + 安全合规率的加权和）
    → 目标期刊: IEEE Access、Complexity、Journal of Ambient Intelligence and Humanized Computing

方案 B（稳妥，冲击二区）:
主角算法: DE + 自适应 F/CR（根据种群多样性动态调整）
    → 改进点: 基于种群分布熵的自适应 F/CR 调整策略
    → 代码量: < 300 行
    → 对比实验: 标准 DE, jDE, SHADE, GA, PSO（5 个 baseline）
    → 目标期刊: Applied Soft Computing、Expert Systems with Applications
```

## 5. 结论

> 在 **算力有限**（ARM Cortex-A53、每次评估运行完整 RAG 链路）且 **追求快速发表 SCI 二区/三区** 的双重约束下：
>
> **单目标优化是唯一可行路径**。多目标优化因评估代价成倍增加而被排除。
>
> **首选方案**：
> - 若追求 **最高录用率 + 最快发表**：**SSA + 混沌初始化 + Levy 飞行**（三区，3~6 个月）
> - 若追求 **更高期刊档次 + 稳健性**：**DE + 自适应 F/CR**（二区，4~8 个月）
>
> **必须满足的条件**：
> 1. 必须包含 **至少 2 个明确改进点**（不能是直接应用）
> 2. 对比实验必须包含 **至少 5 个近期 baseline**
> 3. 必须包含 **标准 benchmark 测试**（≥10 个函数）和 **MoniBox 应用实验**
> 4. 总评估次数（真实 RAG 调用）应控制在 **< 200 次**，benchmark 阶段可用廉价代理模型
