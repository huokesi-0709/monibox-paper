# Introduction

灾害受困场景中的文本求助通常短促、不完整且带有强烈压力。用户可能同时表达“被困”“流血”“喘不上气”“手机没电”“害怕”等多种信息，也可能明确否认某些风险，例如“腿疼但没有流血”。这类输入对检索增强生成系统提出了不同于一般问答的要求：系统不仅要找到语义相关内容，还必须优先识别风险、避免误触发高风险协议，并在证据不足时保持克制。

普通 RAG 容易把“语义相似”误当成“安全可用”。在灾害文本中，仅依赖关键词或向量相似度可能忽略否定窗口、次级意图和安全边界，从而产生两类问题：一是漏掉真正的高风险需求，二是在低风险或否定样本中误触发高风险处置。对于论文评测而言，这些问题需要被拆成可度量的路由任务，而不是只观察最终回复是否看起来合理。

本文提出并评估 RAIR-RAG，即 Risk-Aware Intent Routing for Retrieval-Augmented Generation。RAIR-RAG 将输入首先映射到风险标签、主意图、次级意图、否定风险和约束信息，再决定路由与检索/回复策略。论文关注的是风险路由与安全约束的可复现评测，而不是声称构建了可直接部署的救援系统。

为支撑评测，本文使用 `benchmarks/rair_rag/` 中的 RAIR-RAG-Bench。当前数据集应被描述为 guideline-informed, human-reviewed synthetic benchmark：样本由模板和候选生成流程构造，经人工仲裁与复核，覆盖否定、多意图和边界场景。需要特别说明的是，当前权威证据链尚未完整填充；`guideline_refs` 主要来自风险标签级映射，`reference_reply` 仍为空。因此论文不能写成“每条样本都有权威来源映射”。

本文的实验比较关键词 baseline、去否定处理、单意图处理、手工风险路由策略和 DE 搜索策略。主结果显示，`risk-router-manual` 在 test 集上取得 RouteAcc 0.8583、HRR 0.8718、PFTR 0.0083、NegRiskF1 0.7246 和 SecondaryIntentF1 0.7055；DE 搜索没有找到优于手工策略的可行配置，应作为校准负结果报告。

本文贡献包括：构建 RAIR-RAG-Bench；定义面向风险路由的评测指标；给出否定、多意图和约束场景的可复现实验；系统比较 baseline、消融和 DE 校准；并明确历史 HSC-DisasterBench-v2 结果与当前 RAIR-RAG 主线的边界。
