# Introduction

灾害受困场景中的人机交互具有强烈的时间压力和风险不对称。用户可能处于地震废墟、坍塌空间、洪涝孤立点或通信不稳定环境中，输入常常短促、重复、情绪化，并伴随受伤、被压、呼吸困难、失温、缺水和电量不足等问题。此类场景要求系统优先识别最高风险需求，而不是平均回应所有信息。

现实部署还受到离线和低算力约束。灾后网络可能中断，远端 API 不可靠或不可用；边缘设备的 CPU、内存、电量和模型容量有限。因此，应急回复生成方法需要在本地知识库、本地检索和确定性配置下运行，并能记录可复现实验 trace。

普通 RAG 在该场景下存在明显风险。仅依赖向量相似度可能把语义相近但风险等级不匹配的 chunk 排到前面；生成模型可能在低证据情况下补全 unsupported claim；若缺少安全护栏，系统还可能输出危险医疗操作、保证获救等不合适内容。

不完美输入进一步放大这些风险。ASR 可能将“流血”识别为“留血”，将“喘不上气”识别为“穿不上气”；口语输入可能包含“救命救命”“啊”“呃”等噪声；长输入可能同时出现被困、出血、恐慌和低电量；否定冲突如“腿疼但是没流血”则要求系统避免误触发出血协议。

为解决上述问题，本文提出 HSC-RAG，即 heuristic safety-constrained RAG。该方法不把安全性完全交给生成模型，而是在输入、路由、检索、重排和输出阶段加入可解释约束。系统先做保守输入归一化，再抽取风险感知多意图，随后用协议门控判断是否命中高风险协议，并对候选证据进行安全约束重排。

本文进一步使用 Differential Evolution 进行离线权重校准。DE 并非本文主方法，而是用于在 dev 数据上优化 HSC-RAG scoring policy 的工具。优化完成后，系统只加载 `policy_de.json` 运行，不在部署阶段执行在线优化，也不使用 test set 调权。

本文贡献包括：提出面向灾害受困场景的 HSC-RAG 框架；建立输入归一化、多意图、协议置信度和安全 trace 机制；提出安全约束重排公式和离线 DE 权重校准流程；构建 clean 与 robustness benchmark、baseline、ablation 和自动表格导出的可复现实验协议。
