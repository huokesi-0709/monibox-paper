# 论文定位与贡献

## 论文定位

本文主线是 RAIR-RAG：面向灾害受困文本求助场景的风险感知意图路由与检索增强生成评测。论文的主数据、主实验和主表格必须来自 `benchmarks/rair_rag/` 与 `build/rair_eval/`，而不是旧的 `artifacts/paper_final_v2/` 或 `build/eval/final_v2/`。

本文不是 MoniBox 系统论文。MoniBox 可以作为工程背景或原型承载平台出现，但不能替代 RAIR-RAG-Bench 的数据集、任务定义和实验结果。

本文也不是 Differential Evolution 算法论文。DE 只用于在 dev 集上搜索风险路由策略参数；当前实验显示 DE 没有找到优于手工策略的可行配置，因此应作为校准尝试和负结果报告，而不是主要性能贡献。

## 研究问题

1. 在灾害受困文本中，风险感知路由是否能比关键词或弱化组件的 baseline 更好地区分高风险、低风险和边界输入？
2. 否定表达是否会导致协议误触发，显式否定处理能否降低 PFTR？
3. 多意图输入中，系统是否能保留主风险并识别次级意图？
4. 在 dev 集上使用 DE 搜索策略参数，是否能稳定优于人工策略？

## 贡献点

1. 构建 RAIR-RAG-Bench：一个指南启发、人工复核的合成基准，覆盖灾害受困文本中的高风险、低风险、否定、多意图和域外输入。
2. 定义 RAIR-RAG 评测任务：以路由准确率、HRR、PFTR、NegRiskF1、SecondaryIntentF1 和 ConstraintF1 衡量风险路由质量。
3. 提供可复现实验协议：统一从 `benchmarks/rair_rag/data/gold/rair_gold_all.jsonl` 生成 dev/test 与子集，并在 `build/rair_eval/` 输出预测和 summary。
4. 系统比较 baseline 与消融：包括 `keyword-baseline`、`no-negation`、`single-intent`、`risk-router-manual` 和 `risk-router-de`。
5. 明确证据边界：当前可以称为 guideline-informed, human-reviewed synthetic benchmark；不能声称每条样本都有完整权威来源映射，也不能声称存在逐例 `reference_reply`。

## 历史材料边界

`artifacts/paper_final_v2/` 是 HSC-DisasterBench-v2 / HSC-RAG-DE 的历史实验包，不是 RAIR-RAG-Bench。它可以在相关工作、系统演化或附录背景中简短提及，但不得与 RAIR-RAG 主表混排，不得作为当前论文主结果来源。
